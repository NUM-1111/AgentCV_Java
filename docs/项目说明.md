# AgentCV / Job Agent Java — 项目说明

本文档从三个维度概括本仓库：**要解决的业务问题**、**已实现的功能点**，以及**与各 HTTP 接口相关的技术亮点**（与 `docs/` 下专题文档互补）。

---

## 1. 本项目解决了什么问题

本仓库是一个面向**求职与招聘场景**的后端服务骨架，核心是用大语言模型（通过 **LangChain4j** 接入 OpenAI 兼容 Chat API）把「非结构化文本」变成「可消费的结构化结果」，并尽量在工程上解决真实落地时的常见问题：

| 维度 | 说明 |
|------|------|
| **业务价值** | 辅助 **JD 解析**、**简历与岗位匹配评估**、**按 JD 重写项目经历**，减少人工阅读和主观偏差，统一输出格式便于前端或下游系统使用。 |
| **可靠性** | 对「人岗匹配」链路单独做了 **输入裁剪、Token 预估与拦截、原始模型文本中的 JSON 提取、字段名归一化、反序列化与 Bean 校验**，降低长文本溢出、模型输出格式漂移导致的失败率。 |
| **可观测性** | 通过 **TraceId（MDC + 响应头）**、**HTTP 层 AOP**、**匹配评估专用 AI 调用 AOP**，在不全量打印敏感正文的前提下记录耗时与关键指标，便于排查问题。 |

技术栈概览：**Spring Boot 3.2**、**Java 17**、**LangChain4j 0.36.x**（`langchain4j-spring-boot-starter` + OpenAI 兼容 starter）、**Spring AOP**、**Jakarta Validation**、**Jackson**（自定义宽容读配置）。

## 2. 本项目确定的功能点

以下为代码中已暴露或可观测的**确定能力**（以当前 `src/main/java` 为准）。

### 2.1 HTTP 接口

| 方法 | 路径 | 作用 |
|------|------|------|
| `GET` | `/ping` | 健康探测，返回 `pong`。 |
| `POST` | `/api/v1/jd/analyze` | 根据 **JD 纯文本**解析结构化信息（岗位名、核心职责、硬性技能等）。 |
| `POST` | `/api/v1/match/evaluate` | 根据 **JD 纯文本**与**简历纯文本**生成结构化 **人岗匹配报告**（分数、匹配/缺失技能、改进建议）。 |
| `POST` | `/api/v1/resume/rewrite` | 根据 **目标 JD** 与 **候选人原始项目经历文本**，按 STAR 思路重写要点并给出优化说明。 |

### 2.2 请求校验与错误行为（共性）

- 各业务接口对必填字符串做 **非空 / 非纯空白** 校验，不满足时抛出 `IllegalArgumentException`，由 `GlobalExceptionHandler` 统一映射为 **HTTP 400**。
- **`/resume/rewrite`** 额外对 `jdText` 和 `originalProjectText` 做 **3000 字符长度上限** 校验，超出返回 HTTP 400。
- **匹配评估**在业务层另有：`ContextWindowExceededException`（输入过长，预估 Token 超限 → 400）、`AiOutputValidationException` 与解析失败（模型输出不符合约束 → 500 等），具体以 `GlobalExceptionHandler` 为准。

### 2.3 横切能力

- **TraceId**：每个请求生成短 ID，写入 **SLF4J MDC** 与响应头 **`X-Trace-Id`**，与 `logback-spring.xml` 中的 `%X{traceId}` 配合打全链路日志。
- **日志切面**：所有 `@RestController` 方法记录方法、URI、入参摘要、耗时与成败；**匹配评估**在 `MatchEvaluationFacadeService.evaluate` 上另有专用 **AI 调用日志**（长度、耗时、分数与列表条数等，不打印全文）。

### 2.4 配置与运行

- 通过 **`.env`（dotenv-java）** 在启动时注入系统属性，供 **`application.yml`** 中 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL_NAME`、`SERVER_PORT` 等占位符使用。
- LangChain4j 侧可开启 **请求/响应日志**（`log-requests` / `log-responses`），调试时可结合 `dev.langchain4j` 的日志级别查看 Prompt 与原始响应。

## 3. 接口相关的亮点技术（按能力拆分）

### 3.1 `POST /api/v1/jd/analyze` — JD 解析

- **LangChain4j `@AiService`**：用接口 + 注解声明 **系统提示 / 用户消息模板**，由 Spring 集成生成调用实现，Java 侧以 **`JdInfo` 记录类型**作为结构化输出载体。
- **`@Description`（字段级）**：在 `JdInfo` 的各字段上标注语义，便于框架将「期望字段含义」编码进结构化生成流程，约束模型按业务语义填充（岗位名、职责列表、技能列表等）。

### 3.2 `POST /api/v1/match/evaluate` — 人岗匹配（工程化最重）

- **双阶段设计**：`MatchEvaluatorService` 仅负责 **返回模型原始字符串**（提示词中强制「只输出 JSON」）；`MatchEvaluationFacadeService` 负责 **裁剪 → 限长 → 解析 → 校验** 的完整编排，与「直接 `@AiService` 映射到 `MatchReport`」相比，可控性更强。
- **`TextTrimmer`**：对 JD / 简历做 **业务向裁剪**（正则 + 段落识别：如职责/要求、工作/项目经历等），过滤噪声行，减少无关 Token，从源头缓解上下文压力（详见 `docs/上下文窗口优化/`）。
- **`TokenEstimator`**：在调用模型前做 **保守 Token 估算**（中文、非中文分段规则 + 模板固定开销），超限则 **`ContextWindowExceededException`**，避免依赖模型侧不可见的截断行为。
- **非标准 JSON 与漂移治理**：从原始文本 **`{`…`}` 提取 JSON**；**`FieldNameNormalizer`** 在 Jackson 之前对 key 做正则归一化，与 **`MatchReport` 上的 `@JsonAlias`** 形成「模糊变体 + 已知别名」双层兜底（详见 `docs/结构化输出 & 反序列化失败问题/`）。
- **Jackson 宽容读**：`JacksonConfig` 启用注释、尾逗号、单引号等读特性，并关闭 **未知属性即失败**，提高对模型输出轻微瑕疵的容忍度；再用 **Jakarta Validation** 把「能解析」提升为「满足业务约束」（分数范围、非空列表等）。
- **可观测性**：`AiCallLogAspect` 使用 **精准 `execution` 切点** 只切面 `MatchEvaluationFacadeService.evaluate`，避免对工具类或动态代理上的 `@AiService` 误切，聚焦核心 AI 路径。

### 3.3 `POST /api/v1/resume/rewrite` — 简历项目重写（Actor-Critic 双智能体审查流）

- **Actor-Critic 双智能体**：通过 `RewriteCoordinatorService` 编排 `ResumeWriterAgent`（执行者）与 `FactCriticAgent`（审查者）的循环协作，最多 3 轮，以工程手段兜底 LLM 的幻觉问题（详见 `docs/Actor-Critic双智能体审查流/`）。
- **事实边界控制**：`FactCriticAgent` 以 `originalProjectText` 为唯一事实边界，逐条核查 Writer 输出的 bullet points 是否捏造数据或虚构技术栈，返回结构化 `CriticReport`（`approved` + `feedback`）。
- **context 策略**：打回重写时只传 Critic 的 feedback 摘要，不传历史草稿全文，防止 context 随轮次线性膨胀。
- **可观测性**：响应头 `X-Review-Rounds: N` 透出实际审查轮次，方便调试和演示 trade-off。
- **结构化输出**：最终返回 **`RewriteReport`（记录类型）**，包含重写要点列表与优化说明列表，字段带 **`@Description`** 稳定生成质量。

### 3.4 全局与基础设施

- **`TraceIdFilter`（`OncePerRequestFilter`）**：保证每个 HTTP 请求只处理一次，并在 **`finally` 中清理 MDC**，避免线程池复用导致 **traceId 串号**。
- **`WebLogAspect`**：基于 **`@within(RestController)`** 统一记录 Web 层日志；入参通过 **注入的 `ObjectMapper`** 序列化为 JSON 摘要并截断，平衡可读性与体积。
- **`GlobalExceptionHandler`**：对参数错误（`IllegalArgumentException` → 400）、上下文超限（400）、AI 输出校验失败（500）等做分类响应，确保 HTTP 状态码语义正确，便于调用方区分「调用方问题」与「服务内部问题」。
