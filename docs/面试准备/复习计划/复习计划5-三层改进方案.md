### I-1. 效果验证量化体系 🔴 最高优先级

**来源**：真实二面段六（P1）+ 模拟面试Q3 + **字节一面段九（P1——再次承认缺乏量化指标）**

**问题**：AgentCV系统的核心输出质量完全没有自动化度量——连续三次面试暴露同一问题未修复。面试官追问"打分打得准不准"时无法回答。

1. 手动标注10-20组JD的采分点做ground truth
2. 实现采分点向量化+余弦相似度计算

### C-2. Actor-Critic评分逻辑矛盾修正 🔴🔴 最高优先级（三次未修复！）

**来源**：阿里一面P1 → 阿里二面P1 → **字节一面段二P1**

**⚠️ 这是唯一一个经历了三场面仍未修复的P1问题，已从"表述不清"升级为"可能真没想清楚设计"。**

**问题**："权重从重往轻"+"取最大评分"构不成完整逻辑链。

**修复话术（15秒）**：
> "Critic不是在打分后加权加总，而是取最大违规严重度——类似'一票否决'。四个维度各有severity分值（假数据5、假技术4、角色错写3、过度润色2），如果最严重的违规≤2分——说明所有违规都在可接受范围——通过。如果最严重的≥3分——发送feedback让Writer重写。这保证了'宁可误杀轻度违规，也不放过严重捏造'。"

**禁止再说**："权重从重往轻"。

**补充说明（为什么取max而不加权加总）**：
> "取max而不是加权加总的原因：一个简历可能有多处轻微措辞不当，但有一处假数据捏造。加权加总可能让'多处小问题'的总分超过'一个致命问题'——导致假数据被放行。取max保证只要有一条致命违规，整个审查就不能通过。"

### A-1. Java并发编程 🔴 最高优先级

**来源**：真实二面段十五（P0致命）

**A-1.1 线程等待/同步机制速记卡**：

| 机制 | 用途 | 关键API |
|------|------|---------|
| **CountDownLatch** | 等待N个线程完成 | `new CountDownLatch(N)` → `countDown()` → `await()` |
| **Thread.join()** | 等待单个线程结束 | `thread.join()` |
| **CyclicBarrier** | N个线程互相等待 | `new CyclicBarrier(N)` → `await()` |
| **ExecutorService.awaitTermination()** | 等待线程池所有任务完成 | `shutdown()` → `awaitTermination(timeout, unit)` |
| **CompletableFuture.allOf()** | 等待多个异步任务完成 | `CompletableFuture.allOf(f1, f2).join()` |

**A-1.2 话术（30秒）**：
> "最常用三种方案。CountDownLatch——构造时设计数器为子线程数，主线程await()阻塞，每个子线程finally块里countDown()。Thread.join()——主线程for循环对每个子线程调join()。线程池方案——executor.shutdown()后awaitTermination(60, TimeUnit.SECONDS)。"

### A-2. HashMap / Java集合框架 🔴 最高优先级

**来源**：真实二面段十六（P0致命）

**A-2.1 HashMap哈希原理速记卡**：
```
put(key, value)流程：
1. key.hashCode() → 获取32位原始hash值 h
2. (h = key.hashCode()) ^ (h >>> 16) → 高16位与低16位异或扰动
3. (n - 1) & hash → 取模定位桶（n是桶数，2的幂）
4. 桶为空 → 直接放入
5. 桶非空 → equals()判断是否同key
```

**A-2.2 哈希冲突的原因（15秒）**：
> "哈希冲突是数学必然。哈希函数把任意对象映射到有限个桶中——从无限域到有限域的映射，抽屉原理保证必然冲突。"

**A-2.3 线程不安全三场景（30秒）**：
> "JDK7扩容头插法死循环 + size++非原子丢数据 + 扩容读写并发。解决方案：ConcurrentHashMap用CAS+synchronized。"

**A-2.4 hashCode与equals口诀**：
> "hashCode相等不一定equals（哈希碰撞）。equals相等hashCode必须相等（契约）。重写equals必须重写hashCode。"

**A-9.2 循环依赖检测话术（30秒）**：
> "有向图判环。邻接表`Map<String, List<String>>`表示依赖关系。BFS拓扑排序：维护入度表，入度为0的节点入队，每次出队把邻居入度-1，为0时入队。最终出队数≠总节点数则有环。时间复杂度O(V+E)，空间O(V+E)。"
