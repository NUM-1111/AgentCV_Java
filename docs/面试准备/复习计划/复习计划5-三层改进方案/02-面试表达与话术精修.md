## 核心问题

> 自我介绍停留在"我做了X Y Z"而非"我遇到X问题→设计Y方案→效果Z"的叙事结构。
> —— 手录分析·模块二 第5条

三场面试中，面试表达的共性问题可以归纳为五类：（1）叙事结构错误（堆功能而非问题驱动）；（2）术语/数字不精准（"点哈式""大概可能"）；（3）缺少主动引导意识（不把问题往自己项目卖点引）；（4）自我贬低（"心虚""演示大于使用"）；（5）回答停留在产品层不下沉到技术实现。

## C-1. 自我介绍肌肉记忆 🔴 最高优先级

**来源**：阿里二面段一（P2——限定命题下措手不及）+ 手录分析 M2-1, M2-5, M2-12

**问题**：
- 手录指出：自我介绍"存在堆功能的情况，没有出现数据的优化"
- 真实二面：面试官限定"学校里的经历"后措手不及
- 叙事停留在"我做了X Y Z"而非问题驱动的因果叙事

**修复目标**：两种命题下的自我介绍的能脱口而出。

**模板A（30秒 — 开放式命题）**：
> "我叫蒋毅武，哈工程22届。核心项目是Actor-Critic双智能体简历优化系统——用Writer+Critic两个Agent做'生成→审查→循环修正'，解决通用LLM改简历时脑补假数据假技术的幻觉问题。实验验证3轮循环达到87.5%通过率且边际收益递减。技术栈Spring Boot + LangChain4j + DeepSeek。输入侧做了上下文裁剪+Token预估防溢出，输出侧做四层JSON容错pipeline，全链路AOP双切面日志追踪。"

**模板B（45秒 — 限定"学校经历"命题）**：
> "在学校期间，大二加入实验室，参与了两个项目。第一个是AI对话+知识库系统——前端React+Tailwind CSS，后端Go，本地部署模型对接RAG知识库降低幻觉率。第二个是外包CRUD系统。除了实验室，我在课余时间独立开发了一个Actor-Critic双智能体简历优化系统——用Writer生成简历、Critic做四维度事实核查防止AI脑补假数据，技术栈Spring Boot + LangChain4j + DeepSeek。"

**练习标准**：每天早上起床默背一遍，任意环境被叫到都能脱口而出。

## C-2. Actor-Critic评分逻辑矛盾修正 🔴🔴 最高优先级（三次未修复！）

**来源**：阿里一面P1 → 阿里二面P1 → 字节一面段二P1 + 手录分析 M2-6

**⚠️ 经历了三场面仍未修复的P1问题——"权重从重往轻"+"取max"语义相反。**

**修复话术（15秒）**：
> "Critic不是在打分后加权加总，而是取最大违规严重度——类似'一票否决'。四个维度各有severity分值（假数据5、假技术4、角色错写3、过度润色2），如果最严重的违规≤2分——说明所有违规都在可接受范围——通过。如果最严重的≥3分——发送feedback让Writer重写。这保证了'宁可误杀轻度违规，也不放过严重捏造'。"

**禁止再说**："权重从重往轻"。

**补充说明（为什么取max而不加权加总）**：
> "取max而不是加权加总的原因：一个简历可能有多处轻微措辞不当，但有一处假数据捏造。加权加总可能让'多处小问题'的总分超过'一个致命问题'——导致假数据被放行。取max保证只要有一条致命违规，整个审查就不能通过。"

## C-3. 消除"大概/可能" + 硬数据密度提升 🔴 最高优先级

**来源**：豆包模拟面试全场统计7次"大概/可能" + 手录分析 M2-1, M2-9

**修复规则**：所有模拟面试强制禁止使用"大概/可能/应该"。每个数字必须有确定值。

**每个核心模块至少储备1个脱口而出的测试数据**：

| 模块 | 目标数据 | 练习标准 |
|------|---------|---------|
| Token预估 | 8组Golden Set 486-604 | 15秒脱稿 |
| TextTrimmer | "43个用例全过" | 脱口而出 |
| Critic召回率 | "3类dirty draft/9次调用/100%召回率" | 脱口而出 |
| 循环验证 | 50%/80%/87.5% | 脱口而出 |
| Memory A/B | 0 vs 1 violation | 脱口而出 |
| 成本 | I-3完成后补充 | 15秒脱稿 |

## C-5. 假数据判断——从原则下沉到工程实现 🟠 高优先级

**来源**：阿里二面段七（P1）+ 手录分析 M2-7, M2-15

**问题**：面试官问"怎么判断假数据"，回答"以原文为依据"——只说了原则没说机制。

**修复话术（15秒）**：
> "Critic不是简单的字符串匹配。我把原始简历做结构化抽取——提取出技术栈列表、项目名称、量化数据。然后让Critic逐条比对改写后的简历。如果出现原文没有的技术栈——标记为FAKE_TECH。如果原文说'参与开发'改写后变成'主导设计'——标记为EXAGGERATION。"

## C-6. Agent层解决幻觉时主动关联Actor-Critic 🟠 高优先级

**来源**：阿里二面段十一（P1）+ 手录分析 M2-16

**问题**：面试官问"Agent层怎么解决幻觉"，答的是"RAG+提示词+换模型"，唯独没提自己的Actor-Critic。

**修复规则**：当被问"怎么解决幻觉"时**第一句话必须说**："我的做法是用一个专门的Critic Agent做事实核查……"

## C-8. Token估算精准化 🟠 高优先级

**来源**：手录分析 M2-2 + 字节一面段二

**问题**：不同面试Token估算表述不一致。还说过"4个英文=1token"——方向反了。

**正确速记**：
- 中文：1字 ≈ 0.5-0.7 token（即1.5-2字=1token）
- 英文：1单词 ≈ 1.3 token
- 保守估算策略：中文1字≈1token（高估30-50%），英文1单词≈2token（高估约50%）

## C-9. 不要自我贬低 + 缺少对冲说辞 🟠 高优先级

**来源**：阿里二面段二/三/四（P2）+ 手录分析 M2-12

**修复清单**：
- "演示性质大于使用" → "MVP阶段验证了核心链路可行性，现在正在迭代中"
- "比较心虚" → "虽然没参加过竞赛，但在实验室积累了端到端项目交付经验"
- 成绩35%-40% → "在中等水平，但大一大二把比较多时间花在了实验室和自学AI上，核心专业课保持在85分以上"

**核心原则**：暴露弱点时必须附带对冲表述，永远不要自己给自己贴降级标签。

## C-10. 面试沟通姿态 + Face Question回答结构 🟠 高优先级

**来源**：手录分析 M2-8, M2-10, M2-17

**修复清单**：

1. **不提反问句**：永远不说"你不觉得多余吗？"——面试大忌。

2. **先理解问题再回答**：听到问题后，用1-2秒在脑子里确认"他在问什么——产品层还是技术层？"

3. **金字塔结构**（手录第10条）：介绍完整功能链时先说整体架构再往下展开。"从入库到检索完整链路是：文档解析→向量化→Milvus写入→query向量化→IVF_FLAT检索→防幻觉生成"

4. **职业规划要有贡献视角**：不要全是"我要学什么"，加上"我希望在岗位上通过[具体方向]的成长来回馈业务需求"

## C-11. 项目卖点嵌入意识 🟠 高优先级

**来源**：手录分析 M2-16

**问题**：面试官问通用问题时，没有把回答引向自己项目的核心卖点。

**修复规则**：
- 当被问"为什么做这个项目"→ 连带说出幻觉率和Actor-Critic
- 当被问"怎么保证质量"→ 连带说出循环验证+四层容错+三层质量保障
- 当被问"项目难点"→ 连带说出结构化输出的三层不稳定+四层防御

## C-12. Function Calling / Spring AI / 四层Pipeline 速讲话术 🟡 中等优先级

**Function Calling**（20秒）：
> "Function Calling是让LLM在运行时自主决定调用外部函数的能力。我的项目输入完全预知（JD+简历），不需要模型动态获取外部信息，所以没用。StageThree规划了Tool Calling。"

**Spring AI vs LangChain4j**（30秒）：已从复习计划5继承话术，背熟即可。

**四层Pipeline + AOP**：听到"结构""输出""日志"关键词自动触发对应话术。

---

## C-13. SSE增量/全量传输区分 🟡 中等优先级

**来源**：手录分析 M2-3 + 字节一面段十六

**问题**：SSE增量传输和全量传输分不清楚，暴露SSE停留在概念层面。

**修复**：
- SSE使用`text/event-stream` MIME类型
- `data:` 前缀 + `\n\n` 分隔
- 增量传输：每次只传新生成的片段，前端累积拼接
- 全量传输：服务端完整生成后一次性推送

---

## C-14. 质量保障话术（应对"怎么保证质量"追问） 🟡 中等优先级

**来源**：手录分析 M2-14

> "我们有三层质量保障。第一层是Critic的自动审查——四个维度的违规检测，实验数据显示能拦截87.5%的幻觉性改写。第二层是循环修正机制——最多3轮，不满意就重写，每轮都有历史feedback作为约束。第三层是我们在golden-test-set上做了端到端验证——用20组真实JD+简历对做测试，人工标注通过率。目前最大的短板是缺乏自动化的量化评分——这也是我在StageThree规划中要引入的方向。"
