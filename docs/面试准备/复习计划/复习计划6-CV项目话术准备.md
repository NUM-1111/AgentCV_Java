## ⚡ 面试前 5 分钟速查卡

| 你要脱口而出的 | 具体数字 |
|--------------|---------|
| 架构 | 评分(三维 40/35/25) × 改写(Writer) × 审查(Critic+FactCheckTool) 三阶段管线 |
| Critic 四维度 | FAKE_DATA(5) / FAKE_TECH(4) / EXAGGERATION(3) / MINOR_EMBELLISHMENT(2) |
| 判定逻辑 | **取 max severity，一票否决**——≤2 通过，≥3 打回重写 |
| 循环轮数 | 最多 2 轮 Actor-Critic 循环（`DEFAULT_MAX_ROUNDS = 2`） |
| Token 阈值 | 10000 字符 = Trimmer 结构上限 8000 + 模板开销 400 → 反推取整 |
| Golden Set | 9 组真实 JD+简历样本，实测 Token 486~604 |
| Critic 召回验证 | 3 类 dirty draft × 3 采样 = 9 次调用，100% 召回已知违规 |
| 四层防御 | JSON 提取 → 字段名归一化(25+变体) → Jackson 四宽松开关 → Bean Validation |
| 全栈证据 | SSE 阶段级推送（后端）+ 进度条 UI + 复制/导出（前端），AI 辅助跨端 |

### 🚫 面试绝对禁止说

- ❌ "权重从重往轻" → ✅ "取最大违规严重度，一票否决"
- ❌ "大概/可能/应该" → ✅ 每个数字必须有确定值
- ❌ "演示性质大于使用" → ✅ "MVP 阶段验证了核心链路可行性"
- ❌ "这方面接触的没有" → ✅ "我确实没深入了解，但可以试着分析——[给思路]"
- ❌ "二七届" / "creative agent" / 任何方法名口误
- ❌ 沉默超过 10 秒 → ✅ 用超纲公式："我可以试着分析——"

## 🎯 每个亮点的一句定调 + 关键数字

### 亮点 1：Actor-Critic 双Agent改写体系

> **一句定调**：Writer 生成、Critic 做四维度事实核查取 max severity 一票否决，Critic 不是纯 LLM——它有 FactCheckTool 做精确数值比对。
>
> **关键数字**：三维评分权重 40/35/25，max severity ≤2 通过 ≥3 打回，3 类 dirty draft × 3 采样 100% 召回。
>
> 👉 详细话术：[`01-Actor-Critic`](../项目开发/01-Actor-Critic双智能体审查流/05-面试难点合集-Critic审查质量保障.md) | Tool Calling: [`05-Tool调用集成`](../项目开发/05-Tool调用集成/02-面试话术.md) | 评分设计: [`06-简历质量提升`](../项目开发/06-简历质量提升开发计划/02-面试话术.md)

### 亮点 2：完整简历结构感知与局部改写

> **一句定调**：用户粘贴整份简历，ResumeParser 自动分段，只改写项目经历，其余原样保留后回填拼接——防止 LLM 改不该改的内容。
>
> **关键数字**：关键词+正则匹配中英文标题+序号前缀+CRLF/LF 换行，fallback 兜底不丢数据。
>
> 👉 详细话术：[`10-完整简历结构感知`](../项目开发/10-完整简历结构感知与局部改写/01-面试话术.md)

### 亮点 3：四层 JSON 防御 Pipeline

> **一句定调**：LLM 输出的 JSON 有三层不稳定（Markdown 包裹 / 非标准语法 / 字段漂移），四层防御逐层兜底——任一层的失败由下一层接管。
>
> **关键数字**：FieldNameNormalizer 4 条规则覆盖 25+ 字段名变体，Jackson 4 个宽松开关，格式异常最终拦截率 100%。
>
> 👉 详细话术：[`03-结构化输出治理`](../项目开发/03-结构化输出治理/04-面试深度解析.md)

### 亮点 4：上下文窗口治理与 Token 预估

> **一句定调**：10000 不是拍脑袋——从 TextTrimmer 结构上限反推，由 TokenBudgetCalibrationTest 三层约束自动验证。
>
> **关键数字**：Trimmer 压缩至原始 35%，推导链 8000×1.0+400=8400→取整 10000，9 组 Golden Set 实测 486~604 token。
>
> 👉 详细话术：[`02-上下文窗口优化`](../项目开发/02-上下文窗口优化/03-面试深度解析.md) | 完整推导链: [`04-Token阈值决策数据链`](../项目开发/02-上下文窗口优化/04-Token阈值决策数据链.md)

### 亮点 5：SSE 阶段级进度推送 + 全链路 AOP 日志

> **一句定调**：阶段级推送而非逐字流式是产品决策（简历优化不是对话产品），SSE 选型比 WebSocket 轻量，双切面按职责拆分但共享 traceId。
>
> **关键数字**：2 分钟超时，每 10 秒 heartbeat，SCORING/WRITER/CRITIC/COMPLETE 四阶段事件。
>
> 👉 详细话术：[`07-SSE流式输出`](../项目开发/07-SSE流式输出/03-面试话术.md) | 日志话术: [`04-AOP全链路日志`](../项目开发/04-AOP全链路日志系统/02-原理与面试话术.md)

## 🏗️ 全站方向特别准备

### 跨端话术（30 秒）

> "AgentCV 本身就是跨端实践。后端——三阶段 Agent 管线、Token 治理、四层防御——是我独立设计实现的。前端——SSE 进度条对接、EventSource 重连逻辑——是借助 Claude Code 辅助完成的。关键不是我会不会写 React，而是我理解前后端交互的全链路——SSE 的 text/event-stream 协议、heartbeat 防断开——跨端边界的问题我能独立排查。"

### AI 编程工具使用深度（30 秒）

> "FactCheckTool 的 checkClaim 方法——AI 给了第一版正则只能匹配纯数字，我复核发现漏了中文单位（%/倍/万/QPS）和边界情况，修正后覆盖 4 种场景。我的模式：AI 出初稿→我做复核→修正→二次验证。决策权始终在我——比如选择阶段级 SSE 而非逐字流式，是产品决策不是技术限制。"
