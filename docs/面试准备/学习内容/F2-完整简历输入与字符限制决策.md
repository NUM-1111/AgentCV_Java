> **对应需求**：放开 3000 字符限制 → 10000，前端文本框改名"完整简历"
> **涉及代码**：`ResumeController.java`, `index.html`, `TokenEstimator.java`, `TextTrimmer.java`, `TokenBudgetCalibrationTest.java`

## 一、面试核心问题：为什么是 10000，不是 5000 或 20000？

### 1. 决策不是拍脑袋，是从底层反向推导的

```
TextTrimmer.TOTAL_CHAR_LIMIT(8000) → TokenEstimator(8400) → 取整(10000)
       ↑ 结构上限                    ↑ 保守估算              ↑ 安全阈值
```

**推导公式：**
```
Trimmer 理论最大输出: JD 2段×1500 + 简历 3段×1500 = 7500 → 设为 8000（留 fallback 余量）
Token 估算: 8000 字符 × 1.0(中文字符/token) + 400(模板固定开销) = 8400 token
← 这是阈值下限。低于8400，约束A断裂。取整到 10000，留 1600 token 业务增长余量。
```

### 2. 三层自动化验证（TokenBudgetCalibrationTest）

| 约束 | 验证内容 | 结果 |
|------|---------|------|
| **约束A** | TextTrimmer 理论最大输出(8000) + 模板开销(400) = 8400 ≤ 10000 | ✅ 余量 1600 token (16%) |
| **约束B** | Golden Set 9 组真实样本，经 Trimmer→Estimator 完整链路后，实测 token 范围 **486~604** | ✅ 安全系数 10000/604 ≈ 16.5×，远超 3× 最低要求 |
| **约束C** | 英文简历场景，链路不崩溃、核心段落不丢失 | ✅ |

### 3. 面试话术

> "10000 字符限制不是拍脑袋定的。它是从 TextTrimmer 的结构上限(8000字符) + Prompt 模板开销(400 token)反推出来的下限 8400，向上取整到 10000。这个数字由 TokenBudgetCalibrationTest 三层约束自动验证——约束A保证理论最大值在阈值内，约束B用 9 组真实样本实测 486~604 token 确保不误杀，约束C覆盖英文场景。每次修改相关常量后跑测试即可自动校准。"

## 二、为什么不做预处理？（答案是：已经做了）

### TextTrimmer 的预处理能力

在 Controller 校验放行后，`ResumeOptimizationService` 调用 LLM 之前，`TextTrimmer` 会对输入做以下处理：

| 步骤 | 策略 | 效果 |
|------|------|------|
| **垃圾行过滤** | 正则匹配：福利、五险一金、公司介绍、联系方式 等 | 剔除无意义信息 |
| **标题识别** | 14 种标题关键词正则（工作经历/项目经历/核心技能/教育背景等） | 结构感知裁剪 |
| **段落提取** | 只保留 JD 的「岗位职责+任职要求」，简历的「工作经历+项目经历+技能」 | 将输入压缩至原始 35% |
| **智能截断** | 在句号/换行等语义边界截断，而非硬切 | 保证语义完整 |
| **兜底策略** | 识别不出结构时，过滤垃圾行后保留长内容 | 不丢失信息 |

### 完整链路

```
用户粘贴完整简历(≤10000字符)
  → Controller.validate() 放行
  → TextTrimmer 裁剪到 ≤8000 字符（只保留核心段）
  → TokenEstimator 确认 ≤10000 token
  → 发送 LLM
```

## 五、面试追问预案

**Q: 为什么不直接把 TOTAL_CHAR_LIMIT 设成 10000？**

> TextTrimmer 8000 是结构上限（JD 2段×1500 + 简历 3段×1500），不是随便设的。如果设成 10000，那意味着允许更长的段落，但单段 1500 已超过 LLM 有效注意力范围。8000→10000 之间的 2000 字符是留给回填拼接（任务 6 的 `finalResumeText`）用的。

**Q: 10000 能覆盖所有情况吗？**

> 对于当前的"项目经历段"场景，Golden Set 实测 token 峰值 604，10000 有 16.5× 安全系数。后续如果改为完整简历输入（包含教育、技能、多个项目段），TextTrimmer 仍会将输入裁剪到 ≤8000 字符。如果实测发现接近上限，跑 `TokenBudgetCalibrationTest` 会自动给出新的建议值。
