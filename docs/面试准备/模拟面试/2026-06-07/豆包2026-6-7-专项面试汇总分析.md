## 四、成本模块诊断

### 4.1 已掌握的

| 维度 | 证据 |
|------|------|
| 减量 | 能描述从简历提取关键信息（学校/专业/技能/项目/实习）做字符串截断 |
| 提效 | Writer 高 temperature（生动扩写）vs Critic 低 temperature（固化流程）——角色设计理念正确 |

### 4.2 新暴露盲区

| 盲区 | 暴露方式 | 严重程度 |
|------|---------|---------|
| temperature ≠ token 控制 | 面试官直接纠正 "temperature 主要影响输出随机性，对 token 量直接影响不大" | 🔴 硬伤——阿里面试成本题高频 |
| max_tokens 参数 | 面试官追问 "你会考虑怎么用它控制输出成本？" → 回答 "可能不太熟悉" | 🔴 硬伤——这是控制 token 成本最直接的参数 |
| 扩容/长期策略 | 面试提前中断，未展示异步化/队列/缓存思路 | 🟡 中——你有框架储备，但没机会说 |

### 4.3 温度参数的正确关系（面试官已纠正）

```
temperature  → 控制的不是 token 量，是输出的随机性和创造性
max_tokens   → 控制的才是输出长度，这是控制成本最直接的参数

Writer: high temperature（让表达生动）+ max_tokens=800（防止冗长）
Critic: low temperature（让审查稳定）+ max_tokens=600（feedback 应该精简）
```

### 5.3 MDC 异步传递标准答案（面试官已给）

> 自定义 ThreadFactory：在 `newThread()` 中从父线程 MDC 获取 traceId，子线程 run 前 `MDC.put("traceId", ...)`，执行完毕 `MDC.remove("traceId")`。或用 Spring `TaskDecorator` 自动复制。
