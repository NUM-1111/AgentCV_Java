# 01 — 产品需求说明书

---

## 1. 项目定义

> AgentCV 是一个简历优化工具：用户输入 **JD + 完整简历**（文本或文件） → 系统多维评分 + AI 改写项目经历 + 内部事实核查 → 输出一份**可导出的完整优化简历**。

**关键词：多维评分驱动、完整简历进出、改写过程对内不对外。**

## 3. 系统输入输出契约

### 3.1 输入

| 字段 | 类型 | 说明 |
|------|------|------|
| `jdText` | String | JD 文本，支持直接粘贴 |
| `jdFile` | MultipartFile | JD 文件（PDF/MD/Word），与 jdText 二选一 |
| `resumeText` | String | 简历文本，支持直接粘贴 |
| `resumeFile` | MultipartFile | 简历文件（PDF/MD/Word），与 resumeText 二选一 |

### 3.2 输出

**快速评分输出：**

```
ScoreReport {
  overallScore:   int（0-100）
  jdMatch:        { score: int, matchedSkills: [], missingSkills: [] }
  format:         { score: int, issues: [] }
  contentQuality: { score: int, highlights: [], improvements: [] }
  advice:         String（改进建议摘要）
}
```

**完整优化输出：**

```
OptimizationReport {
  // 评分（复用快速评分结果或新评分）
  beforeScore: ScoreReport
  afterScore:  ScoreReport

  // 优化后简历
  finalResumeText: String（完整的优化后简历文本）

  // 改写说明
  changes: [
    { projectTitle: String, originalText: String, rewrittenText: String, reason: String }
  ]

  // 审查结论（对内详细，对外只给结论）
  isReliable:  Boolean（用户看到的：是否可信）
  elapsedMs:   Long
}
```

**关键设计决策：**

| 决策 | 说明 |
|------|------|
| 审查结果不暴露 | 用户只需知道"审查通过"即可，无需看到违规类型、severity 等内部细节 |
| 评分结果缓存 | 快速评分后如果立即点完整优化，不重复调用 LLM 评分 |
| 进度条而非逐字推送 | 用户不需要"跟读"AI 输出，只需感知进度，完成后一次性展示结果 |

## 4. 评分体系（核心引擎）

评分是整个系统的**命脉**——它决定了改写的策略和重写方向。

### 4.1 评分维度

| 维度 | 权重 | 评分依据 |
|------|------|---------|
| JD 匹配度 | 40% | 技能关键词匹配、技术栈覆盖、经验年限对齐 |
| 内容质量 | 35% | 技术深度、量化成果、STAR 结构完整性 |
| 格式规范 | 25% | 排版整洁度、篇幅合理性、信息密度 |

### 4.2 评分如何驱动改写

```
评分阶段输出：
  matchedSkills: [Java, Spring Boot, Redis]
  missingSkills: [Docker, K8s]
  formatIssues:  ["项目一缺少量化数据", "项目二缺少 STAR 结构"]
  contentIssues: ["项目一描述过于笼统", "实习经历未突出技术点"]

  ↓ 注入 Writer Agent 的 System Message

改写阶段：
  - 重点突出 matchedSkills 中的关键词
  - 对原文中有但未体现的技能做 STAR 化改写（不能捏造）
  - 修正 formatIssues 中指出的结构问题
```

## 5. 数据流

```
输入：jdText/File + resumeText/File

  ↓  文件解析（PDF/MD/Word → 纯文本）

用户输入文本

  ↓  ResumeParser.parse(fullResume)

ResumeSections {
  header, education, skills, projects[], experience, other
}

  ↓  Phase 1: 评分（对各 project 逐段评分）

ScoreReport（多维评分 + 改进建议）

  ↓  Phase 2: 改写 + 审查（对每个 project）

对每个 project.body：
  WriterAgent.rewrite(jd, project.body, scoreCtx)
   → WriterDraft { rewrittenBulletPoints, optimizationReasons }
  FactCriticAgent.check(project.body, rewrittenBulletPoints)
   → CriticReport { approved, violations }

  ↓  Phase 3: 回填 + 评分对比

计算 afterScore（改写后重新评分）
拼接 finalResumeText

  ↓  输出

OptimizationReport {
  beforeScore, afterScore,
  finalResumeText,
  changes[], isReliable,
  elapsedMs
}
```

## 6. 导出功能

| 格式 | 实现方式 | 优先级 |
|------|---------|--------|
| 复制到剪贴板 | 前端 `navigator.clipboard.writeText()` | P0 |
| 导出 MD | 直接下载 .md 文件 | P1 |
| 导出 PDF | 后端生成（iText / OpenPDF）或前端 `window.print()` | P2 |

---

## 7. 明确不做的功能

| 功能 | 原因 |
|------|------|
| 无简历用户模板生成 | 属于另一个产品方向，暂不纳入 |
| 历史记录存储 | 时间紧迫，且与项目二有冲突 |
| 审查详情暴露给用户 | 用户不需要知道内部违规类型，只需结论 |
| 逐字/逐句流式输出 | 非对话产品，用户不跟读 |
| 多项目并发 LLM 调用 | 先串行跑通，后续优化 |

## 8. 已决定

| # | 决策项 | 结论 | 理由 |
|---|--------|------|------|
| 1 | 评分权重 | 先写死 40/35/25，后续通过测验数据校准 | 权重需要真实数据验证才有意义，过早配置化是过度设计 |
| 2 | 文件解析库 | PDF→Apache PDFBox，Word→Apache POI（.docx），MD→纯文本，.doc→提示用户转为 .docx | 都是 Java 生态成熟库，无外部依赖 |
| 3 | 多项目处理 | 全部改写，**串行处理**（一个接一个），评分系统对过多项目给出警告 | 串行=顺序执行而非并发，避免 LLM API 限流，先跑通再优化 |
| 4 | ResumeParser | 正则匹配标题关键词分段，失败时全文送 LLM | ResumeParser 就是把完整简历文本拆成"个人信息/教育/技能/项目/实习"的结构化片段，正则快且不消耗 Token |
