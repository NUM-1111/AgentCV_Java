# 03 — 即时缺陷修复：评分→改写闭环 + 全段落改写

> **修复时间**：2026-07-12 凌晨
> **触发原因**：面试前审查发现两处致命功能缺陷——评分结果不传给Writer、仅改写项目经历导致简历观感失衡
> **涉及文件**：`ResumeOptimizationService.java`、`ResumeParser.java`

---

## 缺陷一：评分→改写闭环未打通

### 问题

`optimize()` / `optimizeStreaming()` 中，Phase 1 评分完成后的 `ScoreResult` 仅打日志就被丢弃，Writer 完全不知道评分结果——不知道缺失哪些技能、不知道内容质量改进方向。改写效果完全依赖 Writer 的 SystemMessage 约束，质量不稳定。

### 方案

通过 `criticFeedback` 参数（已有通道，无需改 Agent 接口签名）将评分引导注入首轮 Writer 调用。

### 改动

**`ResumeOptimizationService.java`**：

1. 新增 `buildScoreGuidance(ScoreResult)` — 从评分结果提取 `jdMatch.missingSkills` 和 `contentQuality.improvements`，生成自然语言引导文本：
   ```
   【评分引导】JD匹配度85/100。缺失技能：Redis、RocketMQ。请在改写中自然融入相关经验描述。改进方向：缺少STAR结构中的Action描述；技术深度不足。
   ```
   兜底逻辑：如果评分结果不完整（子维度为null），降级使用 `improvementAdvice` 字段。

2. 新增 `runActorCritic(jdText, originalProjectText, scoreGuidance)` 重载 — 首轮调用时将评分引导拼接到 `buildFeedbackPrompt(r, fb, scoreGuidance)` 产出的文本中。后续轮次仅使用 Critic 反馈。

3. `buildFeedbackPrompt(int round, String fb, String scoreGuidance)` — 三参数版本：`round=0` 时拼接 `<基础约束> + <评分引导>`，后续轮次拼接 `<Critic反馈>`。

4. `optimize()` 和 `optimizeStreaming()` 接入评分引导：
   - `optimize()` L58 → `runActorCritic(jdText, originalProjectText, scoreGuidance)`
   - `optimizeStreaming()` L86-87 → `buildFeedbackPrompt(r, feedback, scoreGuidance)`

### 关键设计决策

| 决策 | 理由 |
|------|------|
| 通过 `criticFeedback` 参数传入，不改 Agent 接口签名 | Writer 已有三个入参（jdText/originalProjectText/criticFeedback），复用第三参数避免改 `@AiService` 接口 |
| 评分引导仅在首轮注入 | 后续轮次是 Critic 驱动的修正循环，评分引导作为初始方向，不需要每轮重复 |
| `buildScoreGuidance` 多级兜底 | jdMatch → contentQuality → improvementAdvice，保证评分模型输出不稳定时仍有引导 |

## 缺陷二：仅改写项目经历，简历观感失衡

### 问题

`optimizeFullResume()` 只对 `sections.projects()` 走 Actor-Critic 循环，`experience`（实习/工作经历）和 `skills`（技能列表）完全原样保留。简历观感失衡——项目段是优化过的 STAR 句式，实习经历和技能还是原始文本，面试官一眼看出是局部 Demo 而非完整产品。

### 方案

实习经历走轻量改写（保留技术栈和量化数据，仅调整句式与 JD 对齐），技能列表走严格保守改写（仅排序优化+关键词对齐，严禁升级技能等级）。复用现有 `writerAgent.rewrite()`，通过 `criticFeedback` 参数传入不同约束文本。

### 改动

**`ResumeOptimizationService.java`**：

1. `optimizeFullResume()` 重写 — Step 3 从单一 projects 循环扩展为三段：
   - **3a: 项目经历** — 保持 Actor-Critic 循环，带评分引导
   - **3b: 实习经历** — 单次 Writer 调用，约束为"仅调整句式与JD关键词对齐，保留所有原有技术栈和量化数据。不得改变角色定位。"，加上评分引导
   - **3c: 技能列表** — 单次 Writer 调用，约束为"严格保守：仅可调整技能排序和措辞，使JD关键词前置。严禁将'了解'升级为'熟悉'，将'熟悉'升级为'精通'。"

2. `optimizeFullResume()` 返回值改为调用 `ResumeParser.reassembleFull()`（新方法），接收四个参数。

**`ResumeParser.java`**：

1. 新增 `reassembleFull(ResumeSections, List<String> rewrittenProjectTexts, String rewrittenExperience, String rewrittenSkills)` — 完整回填拼接，支持改写后的项目经历 + 实习经历 + 技能列表。每个段优先使用改写版本，null 时回退原文。
2. 原 `reassemble()` 改为委托到 `reassembleFull()` 的薄包装。

### 关键设计决策

| 决策 | 理由 |
|------|------|
| 实习经历走单次调用而非 Actor-Critic 循环 | 实习经历大部分是定性描述（"参与XX项目，负责XX模块"），不如项目经历容易捏造量化数据。Critic 审查带来的收益有限，单次调用+强约束足够 |
| 技能列表走"严格保守"约束 | 技能列表改写风险极大——“熟悉Java”改成“精通Java”会被面试官当场识破。约束中明确禁止升级技能等级 |
| 复用现有 `writerAgent.rewrite()` | 不新增 Agent，通过 `criticFeedback` 参数区分改写模式 |

## 流转逻辑变化对比

### 改造前

```
optimize(jd, projectText):
  score = scoringAgent.score()      // Phase 1
  runActorCritic(jd, projectText)   // Phase 2+3 — score 未传入！

optimizeFullResume(jd, fullResume):
  sections = ResumeParser.parse()
  score = scoringAgent.score()
  for each project: runActorCritic(jd, project.body)  // 只改 projects
  reassemble(sections, projects)                       // experience/skills 原样
```

### 改造后

```
optimize(jd, projectText):
  score = scoringAgent.score()                             // Phase 1
  scoreGuidance = buildScoreGuidance(score)                 // 提取评分引导
  runActorCritic(jd, projectText, scoreGuidance)            // Phase 2+3 — score 已传入！

optimizeFullResume(jd, fullResume):
  sections = ResumeParser.parse()
  score = scoringAgent.score()
  scoreGuidance = buildScoreGuidance(score)
  for each project: runActorCritic(jd, project.body, scoreGuidance)  // 项目经历
  writerAgent.rewrite(jd, experience, 实习约束+scoreGuidance)       // 实习经历
  writerAgent.rewrite(jd, skills, 技能约束+scoreGuidance)           // 技能列表
  reassembleFull(sections, projects, experience, skills)              // 全部改写后拼接
```
