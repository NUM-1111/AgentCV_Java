## 任务 6：optimizeFullResume — 串联整个流程

**需求：** 新增方法，接受完整简历文本 → 解析分段 → 对每个项目段调现有管线 → 回填拼接。

**涉及文件：**
- `ResumeOptimizationService.java` — 新增 `optimizeFullResume(String jdText, String fullResumeText)` 方法
- 复用任务 2 的 `ResumeParser`

**伪代码：**
```java
public OptimizationReport optimizeFullResume(String jdText, String fullResume) {
    // Step 1: 解析
    ResumeSections sections = ResumeParser.parse(fullResume);

    // Step 2: 对每个项目段调现有 optimize()
    List<OptimizationReport> projectReports = new ArrayList<>();
    for (ProjectSection proj : sections.projects()) {
        projectReports.add(this.optimize(jdText, proj.body()));
    }

    // Step 3: 回填拼接
    String finalResume = ResumeParser.reassemble(sections, projectReports);

    // Step 4: 返回（TODO: 聚合 beforeScore/afterScore）
    return OptimizationReport.fullResult(..., finalResume);
}
```

**交付产物：**
- `optimizeFullResume()` 方法可编译
- `ResumeParser.reassemble()` 静态方法

**验证方式：**
- 写单元测试：输入包含 2 个项目的简历 + JD，确认 `finalResumeText` 不为空且包含原 header/education/skills/experience 和改写后的 projects

**⚠️ 这个任务依赖 LLM 调用，测试时可能耗时较长。可以先串行跑 1 个项目验证拼接逻辑正确。**

**预估时间：** 30 分钟

## 附录：钩子式简历写作经验（可反哺 Agent Prompt 设计）

在撰写 Resume3.2 时总结出以下规则，后续 Writer Agent 的 System Message 可参考此风格生成简历：

### 核心原则：简历不是设计文档，是钩子合集

- **每条 = 问题 + 概念名 + 效果**，具体实现方式留给面试官追问
- **概念名是钩子**：如"多维评分驱动""一票否决制""结构感知的局部改写"——面试官看到就会问"怎么做的"
- **数字是信任锚**：如"91% 精确率""100% 拦截率""35% 压缩率""40% Token 降低"——不解释怎么算出来的，但数字必须真实

### 反例对比

| ❌ 泄底写法 | ✅ 钩子写法 |
|------------|------------|
| Critic 按 4 类违规（FAKE_DATA / FAKE_TECH / EXAGGERATION / MINOR_EMBELLISHMENT，severity 1-5 分级，max-severity 一票否决） | Critic 基于分级违规检测与一票否决制核查事实准确性 |
| 基于 14 种标题关键词正则裁剪（单段≤1500 字、全局≤8000 字），10,000 token 超限拦截 | 基于标题关键词正则裁剪将输入压缩至原始 35%，配合本地 Token 预估算与超限拦截 |

### 后续应用

- 任务 4 的 `ResumeScoringAgent` System Message 可要求 LLM 输出"钩子式"改进建议（亮概念，不摊实现）
- 任务 6 的 `optimizeFullResume()` 输出的 `finalResumeText` 中的项目经历描述应遵循此风格
