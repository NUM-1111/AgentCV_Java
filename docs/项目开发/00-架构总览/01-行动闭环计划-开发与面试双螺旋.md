# 行动闭环计划：开发与面试双螺旋

> **前提**：已通过 `00-项目拆解方法论-总驾驶舱.md` 的 L1-L6 完成了项目全貌认知。
> **目标**：把开发改进和面试准备拧成一股绳——每次代码改动都产出面试话术，每次模拟面试都暴露下一个要修的缺口。

---

## 核心原则：改一点、说一点、测一点

```
┌─────────────┐      ┌─────────────┐
│  开发改进    │ ←→  │  面试准备    │
│              │     │              │
│ 改一个功能   │ ──→ │ 产出 3 句    │
│              │     │ 面试话术     │
│              │ ←── │              │
│ 模拟面试暴露 │     │ 说的时候     │
│ 下一个要修的 │     │ 发现说不清   │
└─────────────┘      └─────────────┘

每一次循环 = 一个 Action（1-3天完成一个）
```

## Phase 1：修最关键的口子（当前 ~3天）

> **目标**：把 L3 暴露的 3 个 🔴/⚠️ 中"改完立刻有话可说"的先修掉。

### Action 1：experience/skills 接入 Critic 审查（1-2天）

**代码改动**：
- `ResumeOptimizationService.optimizeFullResume()` 中 experience 和 skills 的 `writerAgent.rewrite()` 替换为 `runActorCritic()`
- 为 experience 定制 Critic 审查 Prompt：「重点关注角色夸大——是否将'参与'升级为'主导'、'协助'升级为'从零搭建'」
- 为 skills 定制 Critic 审查 Prompt：「重点关注等级升级——是否将'了解'改为'熟悉'、将'熟悉'改为'精通'」

**产出面试话术**（改完立刻能说）：
> "三段简历内容我做了差异化处理。项目经历完整走 Actor-Critic 循环——防假数据和假技术栈。实习经历走轻量审查——只防角色夸大。技能列表走最保守策略——只防等级升级。不是技术做不到统一处理，而是每段风险类型不同——一段策略做不到最优。"

**验证**：跑 `SprintValidationTest` 确认全链路不崩

---

### Action 2：接上评分闭环 afterScore（0.5-1天）

**代码改动**：
- 在 `optimizeFullResume()` 中，所有改写完成后调用 `scoringAgent.score(jdText, finalResume)` → 赋值 afterScore
- 返回 `OptimizationReport` 时填入 afterScore

**产出面试话术**（改完立刻能说）：
> "评分闭环已打通。改写前评分对比改写后评分——用户能看到匹配度从 82 到 89 的具体提升。这是产品需求说明书第 2 节设计的用户旅程——现在代码完整实现了。"

**验证**：`mvn test -Dtest=SprintValidationTest`

---

### Action 3：端到端走一遍（0.5天）

**做法**：
1. 启动服务 `./start.sh`
2. 准备一份真实的 JD + 你自己的简历
3. 粘贴发请求，观察完整输出
4. 录屏或截图

**产出面试话术**：
> "我拿我自己的简历跑了一遍完整链路。JD 是快手的后端实习岗位，原始简历匹配度评分 78——缺失 Docker 和 K8s。改写后 Critic 审查通过，评分提到 85。这不是虚构的测试数据——就是我真实跑出来的结果。"

## Phase 2：补齐决策验证（Phase 1 完成后，~2天）

> **目标**：L4 中标注 🔴 的决策项，有一个能拿得出手的验证数据。

### Action 4：模型对比小实验（1-2天）

**最小可行方案**（不是企业级大规模测试）：
1. 准备 3 份简历 + 3 个 JD（共 9 组组合）
2. 分别用 DeepSeek V4-Flash、GPT-4o-mini（如果你有 key）、Qwen（如果有）各跑一遍评分+改写
3. 人工看输出，记录 3 个指标：
   - JSON 格式正确率（不需要四层防御干预的比例）
   - 改写的自然度（1-5 分，自己打分）
   - 单次调用成本（从 API 返回的 token 数算）

**产出面试话术**：
> "我在 DeepSeek 和 [另一个模型] 上做了 9 组 A/B 对比。DeepSeek 的 JSON 格式正确率 85%，另一个 92%——但 DeepSeek 成本只有另一个的 1/3。当前阶段我选择成本优先，因为四层防御 Pipeline 可以兜住那 15% 的格式错误。"

## Phase 3：日常双螺旋节奏（长期）

> **每天 1 小时**：30 分钟开发/复习 + 20 分钟自述 + 10 分钟复盘

### 日常模板

```
┌─ 30min 开发/复习 ────────────────────┐
│                                      │
│  从 L3 自查清单挑一个自己说不清的     │
│  → 读代码 → 修改/验证 → 写出 3 句话术 │
│                                      │
├─ 20min 自述 ──────────────────────────┤
│                                      │
│  打开手机录音，用自己的话讲：         │
│  "我今天改了什么 / 看懂什么           │
│   → 为什么这样改                     │
│   → 面试官可能会追问什么"             │
│  讲完听录音 → 卡壳的地方就是盲区      │
│                                      │
├─ 10min 复盘 ──────────────────────────┤
│                                      │
│  在总驾驶舱底部记一条：               │
│  "202X-XX-XX: Action X 完成，        │
│   新增话术：________"                │
│                                      │
└──────────────────────────────────────┘
```

### 每周一次完整模拟面试

- 用复习计划6 的速查卡自检——能脱稿说出 80% 就可以约模拟面试
- 模拟面试后用总驾驶舱的对应层自查清单找出卡壳点 → 变成下一周的 Action
